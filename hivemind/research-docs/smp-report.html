One HiveMind kernel, 9 CPU cores

The kernel starts every core in the machine. Core 0 keeps the shell, devices and the memory graph; the kernel places compute jobs on the other 8. Measured in one QEMU guest (WHPX) on 13th Gen Intel(R) Core(TM) i5-13420H; 3 repetitions where marked, medians shown.

3. When one core is loaded, placement matters

Core 1 spends 60% of its time on a competing load. With static placement (job i on core i mod 8, fixed up front) everyone waits for core 1's share. With dynamic placement the free cores take its jobs. Medians: static 11.13 s, dynamic 6.37 s.

4. Other kinds of job, 1 core vs 8

Matmul jobs are tiny (a few ms). Over the cluster's serial mesh they scaled poorly; here the jobs move through shared memory, so they scale too.

Limits

  • Core 0 does not run jobs; the other cores run only the bounded compute kinds. Agents, the shell, devices and model calls stay on core 0.
  • Jobs run to completion on a core (no preemption); a run can be cancelled between slices.
  • The "competing load" is simulated by the kernel (a spin share per slice), not another real program.
  • Virtual CPUs share 13th Gen Intel(R) Core(TM) i5-13420H's cores with Windows; scaling on real hardware is not measured.
